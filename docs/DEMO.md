# Демо на 7 минут

Сценарий рассчитан на живой показ: 7 минут рассказа, 2 минуты вопросов. Всё, что
показывается, работает локально, кроме самого Jazz — и на этот случай есть план Б.

## За 10 минут до звонка

```powershell
# 1. зависимости (если не ставили)
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-ml.txt

# 2. фронтенд собран, сервер поднят
.\scripts\dev.ps1 -Build

# 3. прогреть модель, чтобы на демо не ждать 20 секунд
.\.venv\Scripts\python.exe tools\asr_bench.py --wav .artifacts\speech\ru-1.wav `
    --text "Коллеги, начинаем планёрку." --model large-v3-turbo --device cuda

# 4. проверить, что всё живо
.\.venv\Scripts\python.exe tools\smoke.py http://127.0.0.1:8000 8
```

Чек-лист:

- [ ] сервер отвечает на `/api/health`, в `pipelines` есть `jazz`
- [ ] в Edge/Chrome нет сохранённого входа в Jazz под чужим аккаунтом
- [ ] тестовая встреча Jazz создана **без лобби**, ссылка скопирована
- [ ] открыта вторая вкладка с `http://127.0.0.1:8000/fake-meeting/?peers=2&audio1=/fixtures/ru-1.wav&name1=Анна&audio2=/fixtures/ru-2.wav&name2=Дмитрий` — это план Б
- [ ] закрыты лишние окна: агент откроет браузер, лучше не мешать

## Сценарий

**0:00–1:00. Задача и ограничение.**
«Есть Jazz, у которого нет публичного API для ботов. Поэтому агент заходит как
участник — так же, как человек. Задача: онлайн-транскрипт, где видно, кто что сказал,
и лица участников.»

**1:00–2:30. Живая встреча.**
Открыть интерфейс, вставить «Адрес видеовстречи», нажать «Подключить агента».
Пока подключается — объяснить, что происходит: браузер, `RTCPeerConnection`, отдельная
дорожка на участника, PCM по 100 мс в Python.

Когда пошёл текст: обратить внимание на три вещи — серые промежуточные гипотезы,
подсветка активного спикера, бейдж лица с процентом.

**2:30–3:30. Главное архитектурное решение.**
«Мы не угадываем спикера. У каждого участника своя аудиодорожка, поэтому «кто говорит» —
это метаданные, а не результат диаризации. Ошибок кластеризации на перекрывающейся речи
здесь просто нет.»

**3:30–4:30. Экспорт.**
Нажать «Скачать» → «Всё в архиве ZIP»: внутри субтитры SRT/VTT, протокол Markdown, JSON, журнал
событий и запись каждого участника в WAV. Отдельно показать SRT с именами спикеров и записи
участников с длительностью — «вот сырой JSONL, из него собирается любой формат».

**4:30–5:30. Если Jazz не пускает (план Б).**
Открыть вторую вкладку с `fake-meeting`, запустить сессию на неё.
«Это встреча-двойник: участники говорят по настоящему WebRTC, звук — из WAV. Тот же код,
кроме входа в Jazz.» Показать двух спикеров и то, что реплики не перепутались.

**5:30–6:30. Цифры.**
WER 5.3 % на синтезе, RTF 0.13 на GPU (0.6 на CPU), финализация 0.5–0.9 с, детекция лица
5 мс. Сразу оговорить: синтез — оптимистичная оценка, на живой встрече будет хуже, поэтому
метрика вынесена в отдельный инструмент (`tools/asr_bench.py`), а не в slide.

**6:30–7:00. Что дальше и что честно не сделано.**
Взять из README раздел «Ограничения»: лобби/SSO ломают вход, микс-аудио потребует
диаризации, идентификация по имени — биометрия и отдельный контур. Показать дорожную карту.

## Вопросы, к которым стоит подготовиться

| Вопрос | Ответ в одну фразу |
|---|---|
| Почему не диаризация? | По дорожкам спикер известен точно и бесплатно; диаризация остаётся для микса (SIP, запись экрана) |
| Почему Python, а не Go? | ML-стек живёт в Python; Go выиграл бы на шлюзе и при десятках параллельных агентов, поэтому граница проведена по «где данные превращаются в смысл» |
| Почему не облачный ASR? | Звук встречи не покидает контур; локальная модель даёт 5 % WER и предсказуемую задержку |
| Что если участников 20? | Одна модель на всех, инференс сериализован, промежуточные гипотезы отбрасываются при занятой модели; при 20 участниках нужен второй воркер и очередь |
| Как масштабировать? | Агент — отдельный процесс с браузером; сессии независимы, журнал событий уже на диске, дальше — очередь задач и пул воркеров |
| Безопасность? | Локальная обработка, журнал и записи только на диске, биометрия не хранится |

## Что показать, если спросят код

1. `backend/app/capture.py` — хук `RTCPeerConnection` и почему он ставится до скриптов страницы.
2. `backend/app/asr.py` — VAD с пре-роллом и обрезкой хвоста, блокировка инференса.
3. `backend/app/session.py` — журнал как источник истины + восстановление.
4. `backend/tests/test_capture_e2e.py` — доказательство, что весь путь работает: браузер → текст.
